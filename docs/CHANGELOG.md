> **0.9.0 里程碑（开发中）**：这一版开始把 PLAN 里「别的 agent 也能用得踏实」那半段补齐。前两刀都落在**最容易伤到人的两个地方**：往用户文件里写东西，和打开别人写的库。
>
> 1. **文件围栏**（`lib/core/fence.js` + `lib/core/agents-file.js`，PLAN §8.3 / U10）：`init --agents` 把 L0 常驻注入写进 `AGENTS.md`（`--file` 可多次或逗号分隔，`CLAUDE.md`、`.cursorrules` 同一条路），`refresh` 原地刷新，`uninstall` 摘干净。判据不是「能写进去」，是**卸载后逐字节还原**——这需要知道当初到底插了几个换行，所以 `sep` 记在块标记里（`<!-- macro-memory:begin sep="2" v="1" -->`）而不是外部账本：卸载可能来自另一个进程、另一个工作区、另一台机器，只有文件自己带着「我是怎么被放进去的」才靠得住。三种结尾（没有尾换行 / 一个 / 两个空行）各一条判据，CRLF 文件里块内也是 CRLF（否则 git diff 整文件翻红）；坏块（begin 在 end 不在）一律拒改，`init --agents` 预检全部目标、有坏块就一个文件都不动，`uninstall` 报坏块并保持文件原样——比自动猜边界删掉用户内容安全。新增自检支 `tools/probe-fence.mjs`（**11 条**，纯函数 + 一次 CLI 端到端，0.2s）。
> 2. **库版本门**（`lib/core/migrate.js`，PLAN P0-5 / U8）：适配层只认不高于自己的库。库的 schema 比适配层新（被更新版本写过）时，`memory_remember` 之类一律只读拒绝，回执说清「库 schema v99 > macro-memory v1」、为什么停、两条真实出路（升级 `npm i -g dsh-macro-memory@latest`，或确认后 `macro-memory migrate`）。版本号用 SQLite 原生的 `PRAGMA user_version`——meow 自己从不碰它（`grep user_version vendor/meow-memory/lib/index.js` 零命中），所以不新建元表、不改表结构，老库「看起来没被改过」。**这一层不主动写盘**：打开老库只读 0，写 `user_version` 只发生在用户显式跑 `macro-memory migrate` 时（真写前先 `vacuumInto` 出一份一致副本，WAL 里可能还有页，`copyFile` 不够）。库比适配层新时**不降级**：那条路只能靠升级适配层。`doctor` 多一行「库版本：适配层 v1 / 库 v0」，CLI 多一条 `migrate [--dry-run] [--to N] [--json]`。自检支 `tools/probe-core.mjs` 加 **`C13` 两条**（伪造 `user_version=99` 的库 → 写入 refused 且话术含两条出路、`migrateSchema` 回 `db-newer` 不降级；v0 老库 `migrate` 到 v1 并出副本后照旧写得进去），28 → **30 条**。
> 3. **归属账**（`lib/core/owner.js`，PLAN P1-2 / U6）：几个 agent 共用一个库之后，写进去的第一件事就变成了「这谁写的、能给谁看」。做法是一张**旁表** `mem_owner`（`CREATE TABLE IF NOT EXISTS`，老库第一次写入时自动补上），不给 meow 的七张层表加一列——`ALTER TABLE` 七次就是七次真迁移，而归属本来就是**我们这一层**的概念（`agentId` 只有宿主知道）。三条纪律：① `owner` 只能由服务端填（MCP 拿 `initialize` 的 `clientInfo.name`，CLI 记 `cli`），工具的入参改不动它，否则「谁写的」可以伪造；② `memory_update` **不换主人**，只把 `last_editor` 换成改的人——改内容不等于改主人；③ 归属记不上不许影响写入，所有异常吞掉只落日志。`scope` 三层默认按层来（`soul` / `user` → `private`，`rules` / `fact` / `lesson` / `topic` / `project` → `workspace`），可显式覆盖成 `global`。读侧在回执里给每条印 `[self]` / `[agent:codex]` / `[global]`，**没有归属记录的老条目一个标签都不加**——不写「未知」那种假话。这一环是**文本层**的：meow 的七层渲染有十几处，改它等于把「回执文案」这条资产整个重做，而「哪个 id 属于谁」是查表得来的事实，标签只是把它印在 id 旁边（认方括号 id `[0mwxux1f6-…]` 与行首裸短 id 两种实测形态，正文里同形的构建号/哈希不误标）。**隔离真的做了，不只是记账**：`exec.visibility.hidden` 由引擎在**执行前**现算（`buildVisibility` → `hiddenFor`，一条 `SELECT id`），meow 在候选池过滤（`filterSearchable`）与 `memory_read` 取行处各问一句 `isHidden()`——别人的 `private` 条目连 top-k 都不占，直读会明说「这是另一个 agent 的 private 记忆，不给你看」，而不是伪装成「查不到」（后者会让人换 cwd 白找一圈）。过滤放在渲染之后是不行的：先给答案再划掉，k 条被占位、时间轴也会漏。三条口径：① 只挡 `private`，`workspace` / `global` 就是拿来共享的；② `owner` 为空的 private **不挡**——0.9 之前写的老条目全都没有归属记录，一挡就是整库消失，那不是隐私是事故；③ 查表失败退化成「都能看」，不降级成「都看不见」。新增自检支 `tools/probe-share.mjs`（**19 条**，临时目录里两个 agent 共用一个库，2.4s）。
>
> 4. **三段召回 + RRF**（`vendor/meow-memory/lib/index.js` 的 `rankScoped`，PLAN §9 / P1-3）：一次检索原来把七层的候选塞进**一个池子**打分，于是三种可比性完全不同的条目被同一把尺子量——`private` 是「我这个 agent 的私事」、`workspace` 是「这个工作区的共同事实」、`global` 是「跨工作区都成立」，而词法分的绝对刻度受池子大小与 idf 分布支配，换个池子就换一套刻度。现在有分段账（`buildVisibility` 带的 `scopes`：`短 id → scope`）就按 scope 切成三段**各自打分**，再用 RRF（`1/(60+rank)`，沿用仓库既有惯例）融合名次——RRF 只吃名次，正是为「刻度不同、名次可比」准备的。三条硬纪律：① **只有一段非空时一个字都不改**，走原来那一句 `rankForSearch`（单 agent / 单 scope 的库逐位一致，既有四千多条断言不该被这一刀吵醒）；② 融合后把分数**归一化到榜首原始分**，`min_rel` 的比例语义、band 断崖、回执里印的分数都还是同一套量级，不用为了换排序去动十处阈值；③ 偏置**乘在 RRF 贡献上**而不是给最终分数再乘一遍（后者会随段数变化而变味），默认本 agent 的 `private` ×1.3，`private_boost: 0` 关掉、`rrf: false` 整个退回单池。**代价写在明处**：RRF 里每一段的第一名都从 rank 1 起算，所以**段小就占便宜**——`private` 段通常只有几条，它的榜首天然压过 `workspace` 段的榜首，这也正是偏置只取 1.3 而不是 3 的原因；要让「相关度」而不是「段大小」说话，得等 P1-3 的量测（PLAN 原话「调之前先量」）。新增自检支 `tools/probe-rrf.mjs`（**8 条**：单段逐字节退回单池、三段顺序真的变了、偏置把单池末位的私事抬到首位、关掉偏置就回原位、分数仍是词法量级、别人的 private 不进任何一段、归属表没了退化成单池、非法参数不炸）。
>
> 5. **单写者服务 `serve`**（`lib/core/serve.js` + `lib/core/client.js`，PLAN §5、§6 / P1-1 / U7、U9）：两个 agent 同时写一个库，是这类插件唯一真会丢数据的坏——其余都能修，丢的那条修不回来。`macro-memory serve` 起一个前台常驻的单写者，端点信息写进 `<数据目录>/serve.json`（含一次性令牌，`0600`），凡走这套 core 的 agent 探到它就**把读写都交出去**；写按 FIFO 一条一个短事务，请求带 `requestId`，重发同一条 id 只算一次写（服务端去重窗口 5,000 条）。它同时是唯一跑 dream 的、唯一打快照的。**默认不装任何常驻**（LaunchAgent / 计划任务得显式调用，这一版没做，写在明处）。三档模式与回执一一对应：没有 `serve.json` = `standalone` 直连（不装服务的人一次连接都不建、零成本）；探得通 = `shared`；`serve.json` 还在但连不上 = `readonly`——**客户端不偷偷自己写**，这一条落进 `pending.jsonl` 排队，回执明说「这次没有写进库」并给三条路（起服务 / 再调一次 / `detach` 认输），服务回来自动补交（按原 `requestId`，补交也不会写两遍）。唯一例外是令牌对不上（`401`）：当成「这不是我们的服务」回落直连，否则一个换过 dataDir 的旧文件能把整台机器锁成只读。CLI 四条命令：`serve` / `attach`（登记 + 补交）/ `detach`（摘发现文件，服务本身不动）/ `share`（只读看状态），`doctor` 多一行「共享」。新增自检支 `tools/probe-serve.mjs`（**17 条**：`port: 0` 随机端口，含**两个真实子进程各写 200 条 → 400 条不丢不重**、`requestId` 幂等、kill 服务后排队与回来补交、正常关闭后文件自己消失且端口不再接受连接、`noServe` 不被自己的服务截走、`/events` SSE）。
>
> 6. **管理界面 `ui`**（`lib/ui/server.js` + `lib/ui/page.js`，PLAN §10 / P2-1）：看得见才敢信。`macro-memory ui` 起一页，只听 `127.0.0.1`、端口由系统挑、一次性令牌放在 URL 的 `?t=` 里；七页（概览 / 记忆 / 星图 / 注入预览 / agent / 共享 / 运维），首屏 17 KB（判据 ≤200 KB），不引框架、不打包、不联网。三条纪律写死在实现里：① **它不是第二个写者**——界面不直连库，探到在跑的 `serve` 就借它；探不到就在本进程里临时起一个，且 `publish:false`（**不写 `serve.json`、不撤别人的**），关界面就一起停；② 关掉之后进程与端口全消失（`server.close` + 临时 serve 的 `close`），不留守护进程；③ **只读面板一次写都不该有**——`census()` 刻意不建表（老库打开看一眼不该在工作区里落下 `.dsh-meow/`），空库就报空账。为此 serve 补了两块数据面：`GET /census`（分布账：总数 / 三档 scope / 七层 / 层 × scope 矩阵 / 写手）与 `GET /inject`（L0 注入预览与字符数）。判据照 PLAN 的原话：`probe-ui` 12 条里，「界面写一条，另一个引擎实例下次检索立刻读到」「探到现成 serve 就借它且关界面不停别人的服务」「关掉之后端口不再接受连接」「库不存在时只报空账」。
>
> 计数口径：`check-all` **74 支 / 4,740 条**（0.8.1 是 69 支 / 4,671 条；`probe-fence` 11 条 + `probe-core` 2 条 + `probe-share` 19 条 + `probe-rrf` 8 条 + `probe-serve` 17 条 + `probe-ui` 12 条）。

> **0.8.1 里程碑**：这一版治的是**0.8.0 发出去之后，`npx` 那一条路根本跑不起来**。0.8.0 说「一句 `npx -y macro-memory mcp` 就能接上 Codex / Claude Code / Cursor」，实测两句都断。第一处断在**名字**：npm 包叫 `dsh-macro-memory`、bin 叫 `macro-memory`，npx 按包名去执行，于是 `npx -y dsh-macro-memory@0.8.0 doctor` 报 `'macro-memory' is not recognized as an internal or external command`；改用 `-p` 显式指定包之后 bin 找到了，第二处断在**依赖**：`Error [ERR_MODULE_NOT_FOUND]: Cannot find package '@deepseek-ai/dsh-llm' imported from ...\vendor\meow-memory\lib\index.js`。病根很硬：`vendor/meow-memory/lib/index.js` 里有 4 处裸名 import 伸进 DSH 的私有包（`@deepseek-ai/dsh-llm` 三处：`:2`、`:1638`、`:10310`；`@deepseek-ai/schemastery` 一处：`:3`），在本仓能跑只是因为 Node 向上解析撞见了 DSH 的 `node_modules`——**装到别处、换个宿主版本就断**。这一版把两处一起剪掉：
>
> 1. **`@deepseek-ai/dsh-llm` → 自带实现在 `lib/core/compat/dsh-llm.js`**（约 75 行）。这不是「假装实现了」：meow 只用两个符号，而且两个都是纯数据整形——`boundContextSummary(summary)` 就是 `summary.length <= 120 ? summary : summary.slice(0,119) + '…'`，`createUserMessage(input)` 就是 `deepFreeze(structuredClone({...input, id: uuid, role:'user'}))`。compat 层按同一语义实现，另补 `createMessage` / `createSystemMessage` / `createAssistantMessage` / `createDeveloperMessage` 与 `CONTEXT_SUMMARY_MAX_CHARS = 120`，meow 那三处裸名改指过来。
> 2. **`@deepseek-ai/schemastery` → 自带整包**（`vendor/schemastery/`，8 文件 / 115.7 KB；连带 `vendor/cosmokit/`，25 文件 / 64.4 KB）。它的 `lib/index.mjs` 第一行同样伸着裸名 `@deepseek-ai/cosmokit`，一并改成相对路径（上面留了注释说明为什么不能写裸名）。**没有走 npm `dependencies`**：npm 永远不打包 `node_modules` 目录（除非 `bundledDependencies`），而 `dsh-llm` 自身还带 7 个 `@deepseek-ai/*` 子包 + peer `cordis`，整包 vendor 不现实；相对路径补丁让 npx 与 DSH 两条路**跑的是同一份代码**，也不受宿主 DSH 版本漂移影响。
> 3. **命令口径钉死**：文档、`--help`、拒绝写入的提示文案统一改成 `npx -y -p dsh-macro-memory macro-memory <子命令>`；`package.json` 的 `bin` 追加同名别名 `dsh-macro-memory`（指向同一个入口），所以 `npx -y dsh-macro-memory mcp` 也成立。MCP 配置示例的 `args` 同步成 `["-y","-p","dsh-macro-memory","macro-memory","mcp"]`。
>
> 判据不是「本机跑通」，是**裸包跑通**：把 `bin` / `lib` / `vendor` 照 npm 的 `files` 白名单复制到一个**没有 `node_modules`** 的目录（外加 `package.json`），再跑 `node <bare>/bin/macro-memory.mjs doctor --no-nebula` → `引擎：meow=就绪`、`子工具：8 个被融合层收下`、`注入：L0 1266 字符`；`trust` → `已信任`；`remember "裸包能写库了…" --project probe` → `✅ 记忆已写入（fact，id=0mwxqj2u）`；`search "裸包"` 当场命中真库里的历史记忆并带出星图关联——「DSH 里记的，换个 agent 直接查得到」这句承诺，在这一版才真的成立。另用 `npm pack` 出的 tarball 实测 `npx -y -p <tgz> macro-memory doctor` 与 `npx -y <tgz> doctor`（别名）两条路都能起。自检支 `tools/probe-core.mjs` 因此加 **`C11` 两条**（复制裸包并要求输出含 `meow=就绪` + `memory_remember`；三个补丁文件在位）与 **`C12` 两条**（文档里不许再出现 `npx -y macro-memory` 这种 npx 找不到包的写法；`bin` 里必须有包名本身），条数 24 → **28**，`check-all` 仍是 **69 支 / 4,671 条**。0.8.0 已在 npm 上标 `deprecated`，指向这一版。

> **0.8.0 里程碑**：这一版治的是「**这份记忆只属于 DSH**」。到 0.7.1 为止，整个插件的价值——一份真身、星图索引、八个统一工具、1,266 字符常驻注入——全都长在 DSH 的 cordis 宿主上：换到 Codex、Claude Code、Cursor，同一台机器上躺着的那份 `memory.db` 就只是一堆没人读的字节。0.8.0 把**引擎装配**从宿主里剥出来，落成 `lib/core/`（`engine.js` / `paths.js` / `trust.js` / `mini-host.js` / `config.js`）：`mini-host.js` 提供一份最小的 cordis 形状（`tools.register`、`systemPrompt.section`、`settings` / `commands` / `webServer` 三个服务全部本地实现、**不监听任何端口**），两个原引擎一行未改地挂进去；`engine.js` 只导出 `createMacroEngine(opts)` → `{tools, call, injection, trust, close}`，里面不出现任何 `ctx.`、`cordis`、`DSH_HOME` 与 `iframe`。于是同一套 8 个工具、同一段注入、同一张星图，可以给任意 agent 用：
>
> 1. **MCP 服务器**（`lib/mcp/server.js` + `bin/macro-memory.mjs mcp`）——零依赖手写 JSON-RPC stdio，支持 `2025-06-18` / `2025-03-26` / `2024-11-05` 三个协议版本；`initialize` 直接把 L0 注入塞进 `instructions`，客户端不用额外接线；`tools/list` 出 8 个工具（每个带完整 `inputSchema`），`tools/call` 走同一套信任门；stdout 只出协议报文，坏 JSON 回 `-32700` 不断连接。一句 `npx -y -p dsh-macro-memory macro-memory mcp` 就能挂上 Codex / Claude Code / Cursor。
> 2. **CLI**（`macro-memory trust|remember|search|read|project|injection|doctor|stats`）——不开 agent 也能读写同一份库；`doctor` 一条命令自证：版本、数据目录、工作区、库路径、信任状态、引擎就绪、子工具数、L0 字符数，有问题逐条列出并退 1。
> 3. **库还是那一份，位置一个字节没挪**：workspace 库仍是 `<workspace>/.dsh-meow/memory.db`、全局库仍是 `~/.dsh-meow`（装了 DSH 就是 `$DSH_HOME/storages/meow-memory`）。所以 DSH 里存的记忆，Codex 接进来**直接看得见**，不需要同步、不需要导入、不需要第二个库。新加的平台数据目录（Windows `%APPDATA%\macro-memory`、mac `~/Library/Application Support/macro-memory`、linux `$XDG_DATA_HOME/macro-memory`）只放配置、注入块与日志，**不放记忆正文**——派生物和真身分开放。

> **0.6.5 里程碑**：这一版修的是**「标点也是人打的」**——0.6.4 的闸门是「正好一个码点」，于是 `读` 能中、`读？` 又是空手。人真在键盘上问一个字的时候，问号几乎从不缺席：`读？`、`钱。`、`花！`、`「读」` 一个都回不来，等于 0.6.4 只治好了合成语料里那个形状。处方只改闸门：把问句里的标点与空白剥掉再数，**剥完正好一个汉字**才走兜底；汉字之外只许标点或空白——`读1` / `读x` / `读$` / `读+` / `读读` 一律不放行，否则子串匹配立刻退化成噪声源（`probe-gold` 的 G8 会当场红）；找的仍然是剥好的那个字（`hay.indexOf(needle1)`），`读 读` 同一个字重复按一个算。读数：LoCoMo（1,531 问）hit@1 0.3932 / hit@5 0.6192 / hit@10 0.6924 / hit@20 0.7511 / MRR 0.4958 / recall@20 0.6322 / **空回 0.0000**，真库 660 条 52 问三档 0.921 / 0.417 / 0.500 与两条 #2→#1 位移，**又是一位没动**——这一版修的是可达性，不是排序，也不是「多凑几条」。判据 `tools/probe-literal.mjs` 扩到 **18 条**：新增 L9 八种标点逐个命中、且与不带标点的回执同集合 / L10 闸门剥的是标点不是「短」（字母数字符号一个都不放行，纯标点仍旧空手）/ L11 同一个汉字重复按一个算 / L12 标点版三条检索路径同口径 / L13 能红证明（闸门退回「只认一个码点」，`读` 仍中而 `读？` 立刻回空，在子进程里量）。**35 支自检 / 3,599 条断言**。

> **0.6.4 里程碑**：这一版修的是**「一个汉字也是问题」**——切不出词 ≠ 库里没有。`tokenize` 的中日韩那一段只产出**二元组**（`vendor/meow-memory/lib/index.js:1660-1663` 的 `if (run.length >= 2)`），于是一个汉字的问句切出来是空数组：`tokenize('读')` → `[]`、`tokenize('读两遍')` → `['读两','两遍']`。`search()` 的第一道门 `if (q.length === 0 && idents.length === 0) return []` 就这么把它挡回去了——「读」「钱」「花」这类最直白的问法，库里明明白白写着，回执永远是空的。这跟 0.6.2 是同一族病：那条治「剔词剔空」，这条治「压根切不出词」，两条合起来才守得住「回执不全 ≠ 库里没有」。处方窄到只治这一件事：**只有当问句切不出任何词、且问句本身是单个汉字时**，按原文子串在 title / content / keywords 里数命中次数（NFKC + 小写），分数交回 0.6.3 的四把钥匙定序。闸门是「一个码点 + 汉字」，**不是「短」**——`the`/`a` 这类被停用词吃掉的英文问句若做子串匹配就是纯噪声，`probe-gold` 的 G8「没有的事就空手」当场会红；实测 G8 仍是 **空手 10/14** 不变。读数：LoCoMo（1,531 问）hit@1 0.3932 / hit@5 0.6192 / hit@10 0.6924 / hit@20 0.7511 / MRR 0.4958 / recall@20 0.6322 / **空回 0.0000**、真库 660 条 52 问三档 0.921 / 0.417 / 0.500 与两条 #2→#1 位移，**全部逐位不变**——这一版修的是「该回的时候回得出来」，不是「排序还能再挤」也不是「多凑几条」。判据落成 `tools/probe-literal.mjs`（11 条：L1 单字不再空手且每条真含那个字 / L2 只写在 keywords 里也认 / L3 英文停用词仍然空手 / L4 纯标点空白空串仍然空手 / L5 定序不看插入顺序、并列时更新更晚的在前、k 仍生效 / L6 三条检索路径同口径 / L7 能红证明（挖掉兜底即回空，子进程里量）/ L8 库里没有的字仍空手）。同版还**否决了两条候选**并留下负数读数：①**覆盖率优先重排**（top1 覆盖率低于阈值时按覆盖率重排）——真库 thr=0.4 时照抄 0.921→0.947 看着涨，但 LoCoMo 全线下滑：thr=0.25 hit@1 0.3912、thr=0.3 →0.3788、**thr=0.4 →0.3690（−2.4pt）、MRR 0.4743**、永远重排 →0.3442，是真库过拟合；②**缺 id 的脏主键**在入口过滤——会给 `searchIndexOf` 每次造新数组、缓存全失效，性能账不合算（见 `docs/PLAN-0.6.md` §12）。**35 支自检 / 3,587 条断言**。

> **0.6.3 里程碑**：这一版修的是**「同一问句同一答案」**。`search()` 的最后一跳是 `hits.sort((a, b) => (bandOf.get(a) - bandOf.get(b)) || (b.score - a.score))`——分数并列时没有第三把钥匙，V8 的稳定排序就**保留语料顺序**：同一份 40 条同构语料，原序问出 `t-00..t-04`，打乱（seed=1）问出 `t-31,t-23,t-28,t-38,t-27`。生产里 docs 的顺序不是我们给的（存储层更新会改 rowid、VACUUM 与分页会换顺序），所以「谁先进库谁在前」等于**结果由存储布局决定**，对外报的每个读数都只是「抽到的那一次」。修法是把定序换成四把钥匙：**分档 → 分数 → 更新得更晚的在前 → id 自然序**（`D1:2` 排在 `D1:10` 前面），四把全是数据本身的属性，与语料顺序无关；同类的两处一起收掉——`searchAdaptive` 自适应 idf 挑簇原来按语料下标定序（`|| x - y`），两处 `localeCompare`（随 ICU/locale 变，换机器就换顺序）改走码元序但数字段按数值比。**id 自然序是被读数逼出来的**：第一版用纯字典序，LoCoMo 上 hit@1 0.3932→0.3926、hit@5 0.6192→0.6179、hit@20 0.7511→0.7505、MRR 0.4958→0.4953（因为 `D1:10` 被字典序排到 `D1:2` 前面，正好与时间序相反）；改成数字段按数值比后读数**一位不差**回到 0.3932 / 0.6192 / 0.6924 / 0.7511 / MRR 0.4958 / 空回 0.0000，真库 660 条 52 问三档（0.921 / 0.417 / 0.500）与两条 #2→#1 位移也不动——确定性上去、读数没让。判据落成 `tools/probe-determinism.mjs`（9 条：D1 同进程连跑五次逐位相同 / D3 打乱三种 seed / D4 `searchAdaptive` 跨 idf 闸门同样顺序无关 / D5 并列时更新更晚的在前 / D6 id 自然序 / D7 定序里没有 `localeCompare` / D8 能红证明 / D2 跨进程哈希一致），并把「挖掉梯子就换前十」在子进程里验过一遍。**34 支自检 / 3,569 条断言**。

> **0.6.2 里程碑**：这一版修的是一个**把「有」说成「没有」**的缺陷。英文量尺（LoCoMo 10 段 / 5,882 轮 / 1,531 问，`node tools/bench-locomo.mjs --data=…`，零 LLM 零网络）量出 **8 问回执为空**——病根不是「词库小」，而是噪声地板（剔 df ≥ 一半的「到处都是」的词）**剔掉了唯一能命中的那个词，留下一个库里根本不存在的词顶位**：`What Console does Nate own?` 切成 `consol`（库外）+ `nate`（629 条里 454 条有，df 比 72%）→ 剔 `nate`、留 `consol` → 候选择集为空。护栏②只管「剔完一个词不剩」，不管「剔完还剩个不可能命中的」。处方：留下的词全都命中不了时，把**被噪声地板剔掉、且不是虚词**的那些词救回来（`zzzz nate` 里 `nate` 是 72% 的高频词，必然命中；`zzzz 什么` 里 `什么` 是虚词，救回来就是硬凑——一个都不救）。**第一版更宽**（把「问句里所有库里存在的词」都救回来），被 G8「没有的事就空手」当场判红：14 条无关问句里 `光合作用的暗反应发生在哪里`、`上一届世界杯冠军是谁` 立刻被 `合作/作用/反应`、`冠军/世界` 凑出回执（空手 10/14 → 8/14），于是收窄成只救噪声词，两条都满足。读数：**空回 0.0052 → 0.0000**，hit@1/5/10/20 与 MRR **逐位不变**（0.3932 / 0.6192 / 0.6924 / 0.7511 / 0.4958），真库 660 条 52 问三档读数也**一位不动**，G8 空手 10/14 与改前相同——这条修的是「该回的时候不回」，不是「排序还能再挤一点」，也不是「多凑几条」。判据落成 `tools/probe-empty.mjs`（14 条：E1 库外词不顶位 / E2 不凭空编 / E3 老护栏不回退 / E4 正常问句两态逐位相同 / E5 不引新 id 与 k 边界 / E6 成本 0.05ms / E7 只救噪声词、虚词一个都不救），并把「挖掉补丁就变红」验过一遍。同版**否决了两条候选**并留下负数读数：英文词形归一（stem/复数双边合并）**−3.0pt hit@20 / −3.6pt MRR**；MMR 重排最优档只 **+0.66pt hit@20** 且 hit@5 略降，属噪声级——都不落地（见 `docs/PLAN-0.6.md` §12）。**33 支自检 / 3,554 条断言**。

> **0.6.0 里程碑**：这一版回答的是**「库变大之后它会不会自己变钝」**。同一批问句，146 条池子里照抄 hit@1 0.977，喂到 578 条真库只剩 0.889——掉的那 8.8pt 不是答案变差，是**全库统计把区分词磨平了**：`剂量` 在 40 条池里稀有（idf 高），在 578 条里到处都有（idf 掉），而多条干扰项各命中几个常见词，累加就翻了正解。修法是把 idf 算两次、在「这次问句的主场」里再算一遍：先按全库 idf 扫一遍取候选窗口，比每个词「窗口内普及度 / 全库普及度」挑出区分词（比值 ≥1.5 且全库 df ≥2），跟榜首共享区分词的条目自己长成一个簇（8 条），簇内 df 用 Dirichlet 先验向全库收缩（α=100），双尺度按 `λ` 混起来，`λ` 由榜首与第二名的 margin 自定（>0.15 → 0，与 0.5.0 逐位相同）、上限 **0.3**（这条上限是量出来的，不是排出来的）。规模闸门 **N≥300**，小库一个字节不动。读数（真库快照 660 条 active / 52 问，`node tools/probe-idf.mjs` 钉等价、读数在 `docs/PLAN-0.6.md` §1）：**照抄 hit@1 0.895 → 0.921、MRR 0.934 → 0.947；换说法 hit@1 0.333 → 0.417、MRR 0.528 → 0.569；时间锚 0.500 不动；误伤 0、移位 0**，逐题只有两条改动（都是 #2→#1）。回执顺带透传 `status`（不参与打分）。**32 支自检 / 3,536 条断言**。三档同尺横比（同一份冻结语料只换引擎）里 **v0.3.0 / v0.4.0 / v0.5.0 逐位相同，只有 0.6.0 双升**。
