## 3. 设计（五步，全部只用库里已有统计，零 LLM、无手写词表）

> **落地时改了两处口径**（照 §5 定稿）：粗召回窗口 `top-M` 从 64 收到 **8**（64 净负）；簇「累计覆盖候选质量 60%」这条在 8 条窗口上够不到，定稿改成**取满窗口（cover=0）**。下面第 2 步保留草案原文，看的时候以 §5 为准。
1. **双尺度 idf**：`idf_global`（全库）+ `idf_cluster`（这次查询现算的簇）。
2. **簇由数据自己长**：全局 idf 粗召回 `top-M=64` → 对每个查询词算 `df'/M` 与 `df/N` 的比值；比值≈1 视为泛词、≫1 视为**区分词**；取「与榜首共享最多区分词」的条目成簇，累计到覆盖候选质量 60%（硬下限 8 条）。**不引入 project / 标签 / 词表**。
3. **λ 随稀释度自调**：`margin = (score1 − score2) / score1`；`margin > 0.15 → λ≈0`，`margin < 0.05 → λ→1`，中间线性。小库自然 λ≈0，真库自然 λ→1。
4. **反馈续长**（可选，二期）：用已有 `hit_count` / `read_count`——top1 被 read 则簇统计加权；只被检索没被读则同形态下次降权。
5. **顺带产体检项**：稀释度进 `memory_admin(action="hygiene")`，报「近 30 天问句里处于被稀释状态的比例」，让「库变钝」有走势。

λ 的实现只用一行插值，核心是：

```
pG = df(t) / n                                  // 全库频率
p  = (dfL(t) + α·pG) / (n_cluster + α)          // 簇内频率，Dirichlet 往全库拉
idf_local = log(1 + (1−p)/p)
idf_used  = (1−λ)·idf_global + λ·idf_local
```

## 8. 未决问题（**四问已答，答案就是落地时用的口径**）

3. **`searchAdaptive` 第二遍（词形桥）吃不吃局部 idf？** → **不吃**，第二遍显式传 `adaptiveIdf: false`。双遍实测不比单遍好（双遍 α20/W5 能把换说法 hit@3 抬到 0.833，但照抄仍有 1 例误伤），改动面翻倍、收益在噪声里。

## 13. 踩坑账（做原型期间踩到的，别重复）

- **横比必须冻结语料 + 每引擎深拷贝**：同一份 `docs` 反复喂不同 `opts` 跑 `search`，结果会漂——同一道题基线名次一次读到 `0`、另一次读到 `-1`，排查半天才发现索引缓存按 docs 身份挂的。做法：先 dump 成 `corpus.json`，每个变体 `structuredClone` 一次。
- **`rankOf` 返回 -1 = 没命中**，打印时 `+1` 就成了 `#0`。我差点把 `#0→#4` 读成「原本第一被挤到第五」的误伤，实际是「基线没捞到、自适应给到第五」。打印一律 `r < 0 ? '未命中' : '#' + (r+1)`。
- **性能读数先问「几成是测量装置自己造的」**：原型报 33.8ms/问像超预算 17 倍，拆开发现是脚本把整库又搜了一遍；真实 0.61ms/问。
- **改文件只用 `edit`/`write`，PowerShell 只许读**：`Get-Content -Raw | Set-Content -Encoding UTF8` 打补丁，中文全毁（`['鐓ф妱'` → SyntaxError），白跑一轮。毁在**读侧**（已按 GBK 解码），写侧再正确也救不回。
- **探针不许在评测资产目录里建库**：诊断脚本用 `readdirSync` 前缀匹配选库，先命中自己上一版 `Meow.getDb` 造出来的空库，连跑两轮都打印 `empty`，白改一次 `edit`。先 `console.log(candidates)` 再取。
